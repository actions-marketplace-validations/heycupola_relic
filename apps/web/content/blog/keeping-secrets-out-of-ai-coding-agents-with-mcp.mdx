AI coding agents like Cursor, Claude Code, Codex, and Zed need to run your test suite, execute database migrations, and verify builds. Most projects store those credentials in a local `.env` file at the root of the repository.

That creates an uncomfortable trade-off:

1. If you let the AI agent read your workspace freely, it can read `.env`, `.env.local`, or `.dev.vars` and send production or staging credentials into an external LLM context window.
2. If you block the AI from accessing your environment variables altogether, it cannot run integration tests, typegen scripts, or local servers that depend on those variables.

We built `relic mcp` and our runtime injection pipeline to solve this at the process level, without forcing you to give up a familiar `.env` workflow.

## Why `.env` Files Leak Into Prompts

Even when you add `.env` to `.gitignore` or `.cursorignore`, plaintext files on disk remain fragile:

- Agents running shell commands (`cat`, `grep`, `env`, `printenv`, or test runners that dump config on failure) can print secret values directly to stdout or stderr.
- Copying `.env` files between machines or sending them to teammates over Slack leaves plaintext credentials scattered across chat history and downloads folders.
- A single accidental `git add -f` or misconfigured `.env.production` file can push live keys into git history.

## How Relic Separates Secret Names From Secret Values

Relic encrypts every secret value on your device using AES-256-GCM and Argon2id before anything is uploaded. Our servers only store ciphertext.

If you already have a `.env` file, you do not have to rewrite your setup from scratch. You can import it in one command or paste it directly into the terminal UI (`relic`):

```bash
relic login
relic init
relic import .env -e development
```

Once your secrets are in Relic, you can remove the plaintext `.env` file from disk and run commands through Relic's native Rust runner:

```bash
relic run -e development -- bun test
```

Or open a subshell where your variables are loaded in memory for your session:

```bash
relic shell -e development
```

## Giving AI Agents Safe Access with `relic mcp`

Relic includes a built-in [Model Context Protocol (MCP)](https://docs.withrelic.com/development/mcp) server over stdio. It gives your AI assistant the ability to inspect your project structure and run commands with secrets injected, while keeping the decrypted values out of the prompt context.

### 1. Register the MCP Server

In **Claude Code**:

```bash
claude mcp add relic -- relic mcp
```

In **Cursor** (`.cursor/mcp.json`):

```json
{
  "mcpServers": {
    "relic": {
      "command": "relic",
      "args": ["mcp"]
    }
  }
}
```

In **Codex**:

```bash
codex mcp add relic -- relic mcp
```

### 2. What the AI Can (and Cannot) See

The MCP server exposes five tools to the assistant:

| Tool | What it does | Exposes secret values? |
| --- | --- | --- |
| `whoami` | Checks the authenticated user and plan | Never |
| `get-current-project` | Reads `relic.toml` in the workspace | Never |
| `list-projects` | Lists projects, environments, and folders | Never |
| `list-secrets` | Lists secret key names and scopes in an environment | **Names only, never values** |
| `run-with-secrets` | Runs a command with secrets injected into the child process | **Redacts secret values from stdout/stderr** |

When the AI calls `list-secrets`, it sees that `DATABASE_URL` and `STRIPE_SECRET_KEY` exist in `staging`, so it knows which environment variables your code can rely on.

When the AI calls `run-with-secrets` to run `["bun", "test"]`, Relic decrypts the secrets locally on your machine, injects them into the child process, and scans stdout and stderr before returning the output to the assistant. Any secret value of 4 or more characters is replaced with `[REDACTED:KEY_NAME]`:

```text
Connecting to database at [REDACTED:DATABASE_URL]...
✓ 42 tests passed
```

The command also runs with all `RELIC_*` credentials stripped from its environment and is automatically terminated if it exceeds the timeout.

## Catching Missing Keys and Accidental Commits

Alongside `relic mcp`, two more tools help keep both human and AI commits clean:

- **[VS Code and Cursor Extension](https://docs.withrelic.com/guides/editor):** Warns inline when your JavaScript, TypeScript, or Python code reads `process.env.X` or `os.environ["X"]` for a key that is missing in the selected Relic environment, and lets you debug with `"relic": true` in `launch.json`.
- **[Leak Guard (`relic guard`)](https://docs.withrelic.com/guides/leak-guard):** Installs a pre-commit hook that blocks staged `.env` files and scans staged diffs for exact occurrences of your decrypted secret values using a local Aho-Corasick matcher.

```bash
relic guard install
relic check -e production --scan src
```

## Get Started

Relic is open source and free for individual projects, including client-side encryption, the CLI and TUI, the VS Code and Cursor extension, `relic mcp`, `relic guard`, and direct platform sync (`relic push`).

Install the CLI and link your first project in under a minute:

```bash
curl -fsSL https://withrelic.com/install | bash
relic login
relic init
```

Read the full [MCP Server documentation](https://docs.withrelic.com/development/mcp) or star the repository on [GitHub](https://github.com/heycupola/relic).
